# Story 2.1: Sidebar dynamique filtree par role

## Status: Ready for Review

## Story

**As a** utilisateur connecte,
**I want** voir uniquement les menus correspondant a mon role,
**so that** je ne sois pas distrait par des fonctionnalites qui ne me concernent pas.

## Acceptance Criteria

1. Le `SUPERADMIN` voit uniquement : Dashboard Admin, Tenants & Cliniques, Utilisateurs, Permissions
2. Le `CLINIC_ADMIN` voit : Dashboard, Patients, Praticiens, Consultations (sous-menu), Planification (sous-menu), Comptabilite (sous-menu), Utilisateurs de la clinique
3. Le `PRACTITIONER` voit : Mon Dashboard, Mes Patients, Mon Planning, Consultations, Prescriptions, Resultats labo
4. Le `EMPLOYEE` voit : Dashboard, Patients, Planification, File d'attente, Facturation
5. Le `ACCOUNTANT` voit : Dashboard Comptable, Factures, Paiements, Depenses, Tarifs & Prix
6. Le menu est reactif (mobile overlay, desktop persistent) comme actuellement

## Dev Notes

### Fichier principal

`components/layout/sidebar.tsx` — Le tableau `navigation` (lignes 46-110) definit tous les items. La fonction `isItemVisible()` (ligne 125-128) filtre par roles. Le composant `renderNavItem()` (ligne 134) rend chaque item. [Source: architecture.md#source-tree]

### Approche recommandee

Garder la meme structure `NavItem[]` avec le champ `roles?: string[]`. Chaque item qui n'a pas de `roles` est visible par tous. Ajouter les roles manquants.

```typescript
const navigation: NavItem[] = [
  // SUPERADMIN only
  { title: 'Dashboard Admin', href: '/admin/dashboard', icon: Home, roles: ['SUPERADMIN'] },
  // CLINIC_ADMIN + EMPLOYEE
  { title: 'Tableau de bord', href: '/dashboard', icon: Home, roles: ['CLINIC_ADMIN', 'EMPLOYEE'] },
  // PRACTITIONER only
  { title: 'Mon Dashboard', href: '/practitioner/dashboard', icon: Home, roles: ['PRACTITIONER'] },
  // ACCOUNTANT only
  { title: 'Dashboard', href: '/accounting/dashboard', icon: Home, roles: ['ACCOUNTANT'] },
  // etc.
];
```

### Hook useAuth

Le hook `useAuth()` fournit `hasAnyRole(roles: string[])` qui est utilise dans `isItemVisible()`. Pas de changement necessaire au hook. [Source: architecture.md#component-architecture]

### Testing

- **Verification :** Tests manuels. Changer le role dans localStorage et verifier les menus.
- **Pattern :** Pas de tests unitaires frontend.
