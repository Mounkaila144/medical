# Story 1.4: Corrections de securite critiques

## Status: Ready for Review

## Story

**As a** operateur de la plateforme,
**I want** que les failles de securite connues soient corrigees,
**so that** le systeme puisse etre deploye en production en toute confiance.

## Acceptance Criteria

1. CORS configure via `CORS_ORIGINS` env var (ex: `https://app.clinoo.com,https://admin.clinoo.com`)
2. Les secrets JWT sont dans `.env` (non commite) et un `.env.example` documente les variables requises
3. Le fichier `.env` actuel avec les vrais secrets est ajoute au `.gitignore`
4. Rate limiting actif sur `/auth/login`, `/auth/refresh`, `/auth/practitioner/login` : 10 req/min/IP
5. Le package `@nestjs/throttler` est installe et configure

## Tasks / Subtasks

- [ ] **Task 1 : Installer et configurer @nestjs/throttler** (AC: 4, 5)
  - [ ] `cd medicalBackend && npm install @nestjs/throttler`
  - [ ] Ouvrir `medicalBackend/src/app.module.ts`
  - [ ] Ajouter `ThrottlerModule.forRoot([{ ttl: 60000, limit: 10 }])` aux imports
  - [ ] Ajouter `{ provide: APP_GUARD, useClass: ThrottlerGuard }` aux providers (ou appliquer localement)

- [ ] **Task 2 : Appliquer le rate limiting aux endpoints auth** (AC: 4)
  - [ ] Ouvrir `medicalBackend/src/auth/controllers/auth.controller.ts`
  - [ ] Ajouter `@Throttle({ default: { limit: 10, ttl: 60000 } })` sur les methodes `login()` et `refresh()`
  - [ ] Ouvrir le controller de login practitioner et appliquer la meme chose
  - [ ] S'assurer que les autres endpoints ne sont PAS limites (ou avec des limites plus elevees)

- [ ] **Task 3 : Configurer CORS dynamiquement** (AC: 1)
  - [ ] Ouvrir `medicalBackend/src/main.ts`
  - [ ] Remplacer `app.enableCors({ origin: '*' })` par :
    ```typescript
    app.enableCors({
      origin: process.env.CORS_ORIGINS
        ? process.env.CORS_ORIGINS.split(',').map(s => s.trim())
        : '*',
      credentials: true,
    });
    ```
  - [ ] Ajouter `CORS_ORIGINS` dans le `.env` et `.env.example`

- [ ] **Task 4 : Externaliser les secrets JWT** (AC: 2, 3)
  - [ ] Creer `medicalBackend/.env.example` avec toutes les variables requises SANS valeurs secretes
  - [ ] Ajouter `.env` au `.gitignore` du backend (si pas deja present)
  - [ ] Documenter dans `.env.example` : `JWT_ACCESS_SECRET=change_me_to_a_strong_random_secret`

- [ ] **Task 5 : Supprimer les console.log des guards** (AC: general)
  - [ ] Ouvrir `medicalBackend/src/common/guards/roles.guard.ts`
  - [ ] Supprimer les `console.log()` qui exposent les informations de roles

### Configuration ThrottlerModule

```typescript
import { ThrottlerModule, ThrottlerGuard } from '@nestjs/throttler';

@Module({
  imports: [
    ThrottlerModule.forRoot([{
      ttl: 60000,  // 1 minute
      limit: 10,   // 10 requetes max
    }]),
    // ... autres imports
  ],
})
```

Le `ThrottlerGuard` peut etre applique globalement via `APP_GUARD` ou localement sur les controllers auth. La recommandation est de l'appliquer localement pour ne pas impacter les autres endpoints. [Source: architecture.md#security-integration]
