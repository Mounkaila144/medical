# Story 1.3: Corriger l'isolation multi-tenant

## Status: Ready for Review

## Story

**As a** operateur de la plateforme,
**I want** que chaque clinique ne puisse acceder qu'a ses propres donnees,
**so that** la confidentialite medicale entre tenants soit garantie.

## Acceptance Criteria

1. `EncountersService.findOne(id)` filtre par `tenantId`
2. Tous les `findOne()` des services (patients, prescriptions, lab-results, invoices, payments) verifient le `tenantId`
3. Le `TenantGuard` utilise `user.role === AuthUserRole.SUPERADMIN` au lieu de `user.isAdmin`
4. Les endpoints publics (`/public/wait-queue`, `/public/patients/:tenantId`) valident que le tenant existe et est actif
5. Un test verifie qu'un utilisateur du tenant A ne peut pas acceder aux encounters du tenant B

## Dev Notes

### Fichiers a modifier

- `medicalBackend/src/patients/controllers/public-patients.controller.ts` — pas de validation tenant

### Pattern de correction findOne

Avant :
```typescript
findOne(id: string) {
  return this.repo.findOne({ where: { id } });
}
```

Apres :
```typescript
findOne(id: string, tenantId: string) {
  return this.repo.findOne({ where: { id, tenantId } });
}
```

### TenantGuard — probleme actuel

Le guard utilise `user.isAdmin` mais la propriete `isAdmin` n'existe pas sur l'entite User. Il faut utiliser `user.role === AuthUserRole.SUPERADMIN`. [Source: architecture.md#security-integration]

### Testing

- **Framework :** Jest + SQLite in-memory pour E2E
- **Location :** `medicalBackend/src/ehr/__tests__/e2e/` ou `medicalBackend/test/`
- **Pattern :** Utiliser le meme setup que `auth.e2e-spec.ts`
