# Story 3.1: Detection de doublons patients

## Status: Ready for Review

## Story

**As a** receptionniste (EMPLOYEE),
**I want** etre averti si un patient similaire existe deja lors de la creation,
**so that** les dossiers en double soient evites.

## Acceptance Criteria

1. Lors de la saisie du nom et de la date de naissance, un appel API recherche les correspondances
2. Si des doublons potentiels sont trouves, un dialog affiche la liste avec : nom, prenom, date de naissance, MRN
3. L'utilisateur peut choisir "C'est un nouveau patient" pour continuer ou "Voir le dossier" pour ouvrir le patient existant
4. La recherche de doublons est debounced (300ms)
5. Nouveau endpoint backend `GET /patients/check-duplicate?firstName=&lastName=&dob=`

## Dev Notes

### Endpoint backend

```typescript
@Get('check-duplicate')
@Roles(AuthUserRole.SUPERADMIN, AuthUserRole.CLINIC_ADMIN, AuthUserRole.EMPLOYEE, AuthUserRole.PRACTITIONER)
async checkDuplicate(
  @Query('firstName') firstName: string,
  @Query('lastName') lastName: string,
  @Query('dob') dob: string,
  @Req() req,
) {
  const duplicates = await this.patientRepository
    .createQueryBuilder('patient')
    .where('patient.clinicId = :tenantId', { tenantId: req.user.tenantId })
    .andWhere('LOWER(patient.firstName) LIKE LOWER(:firstName)', { firstName: `%${firstName}%` })
    .andWhere('LOWER(patient.lastName) LIKE LOWER(:lastName)', { lastName: `%${lastName}%` })
    .getMany();
  return { duplicates, hasDuplicates: duplicates.length > 0 };
}
```

Note : Le champ tenant sur Patient est `clinicId`, pas `tenantId`. [Source: architecture.md#data-models]

### Debounce frontend

```typescript
useEffect(() => {
  const timer = setTimeout(() => {
    if (firstName.length >= 2 && lastName.length >= 2) {
      checkDuplicates(firstName, lastName, dob);
    }
  }, 300);
  return () => clearTimeout(timer);
}, [firstName, lastName, dob]);
```
