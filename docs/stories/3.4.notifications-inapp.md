# Story 3.4: Centre de notifications in-app

## Status: Ready for Review

## Story

**As a** utilisateur connecte,
**I want** voir les notifications recentes dans le header,
**so that** je sois informe des evenements importants sans quitter ma page.

## Acceptance Criteria

1. Icone cloche dans le header avec badge compteur de notifications non lues
2. Dropdown affichant les 10 dernieres notifications
3. Types de notifications : nouveau RDV, facture en attente, patient en file d'attente, RDV annule
4. Clic sur une notification redirige vers la page concernee
5. Bouton "Tout marquer comme lu"
6. Les notifications sont filtrees par role
7. Implementation initiale : notifications generees cote frontend a partir des donnees existantes

## Tasks / Subtasks

- [ ] **Task 1 : Creer le composant NotificationCenter** (AC: 1, 2, 5)
  - [ ] Creer `components/notifications/notification-center.tsx`
  - [ ] Icone Bell (Lucide) avec badge compteur (nombre de non-lues)
  - [ ] Dropdown (Popover shadcn/ui) avec liste des notifications
  - [ ] Chaque notification : icone, titre, description, timestamp relatif ("il y a 5 min")
  - [ ] Bouton "Tout marquer comme lu" en bas du dropdown
  - [ ] Etat local `useState` pour les notifications (pas de backend pour le MVP — ADR-3)

- [ ] **Task 2 : Generer les notifications depuis les donnees existantes** (AC: 3, 7)
  - [ ] Au chargement du composant, fetcher les donnees recentes :
    - RDV recents (`AppointmentService.getAppointments({ limit: 5 })`) → "Nouveau RDV avec {patient} a {heure}"
    - Factures en attente (`BillingService.getInvoices({ status: 'DRAFT' })`) → "{count} factures en attente"
    - RDV annules recents → "RDV annule : {patient}"
  - [ ] Transformer en objets notification : `{ id, type, title, description, href, read, createdAt }`
  - [ ] Polling toutes les 60 secondes max

- [ ] **Task 3 : Filtrer par role** (AC: 6)
  - [ ] SUPERADMIN : pas de notifications cliniques (ou notifications systeme si disponibles)
  - [ ] PRACTITIONER : ses RDV, ses consultations
  - [ ] ACCOUNTANT : factures en attente, paiements recus
  - [ ] EMPLOYEE : RDV, file d'attente, nouveaux patients
  - [ ] CLINIC_ADMIN : toutes les notifications

- [ ] **Task 4 : Navigation sur clic** (AC: 4)
  - [ ] Chaque notification a un `href` :
    - Nouveau RDV → `/appointments/{id}`
    - Facture en attente → `/accounting/invoices`
    - Patient en file → `/queue/manage`
  - [ ] Au clic, marquer comme lu + naviguer

- [ ] **Task 5 : Integrer dans le header** (AC: 1)
  - [ ] Ouvrir `components/layout/header.tsx`
  - [ ] Ajouter `<NotificationCenter />` a cote du theme toggle et du user nav

## Dev Notes

### Architecture Decision (ADR-3)

Les notifications sont generees cote frontend a partir des donnees deja fetchees. Pas de table notifications en base, pas de WebSocket push. Les notifications se "reinitalisent" a chaque refresh. Un vrai systeme sera implemente en Phase 2. [Source: architecture.md#ADR-3]

### Structure de notification

```typescript
interface AppNotification {
  id: string;
  type: 'appointment' | 'invoice' | 'queue' | 'system';
  title: string;
  description: string;
  href: string;
  read: boolean;
  createdAt: Date;
}
```
