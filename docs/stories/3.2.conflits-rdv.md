# Story 3.2: Detection de conflits de RDV

## Status: Ready for Review

## Story

**As a** utilisateur creant un RDV,
**I want** etre bloque si le praticien a deja un RDV au meme creneau,
**so that** les doubles reservations soient evitees.

## Acceptance Criteria

1. Avant de creer un RDV, le backend verifie qu'aucun RDV existant (statut != CANCELLED) ne chevauche le creneau
2. Si conflit, le backend retourne une erreur 409 Conflict avec le detail du RDV existant
3. Le frontend affiche un message d'erreur clair en francais
4. Verification aussi lors de la modification d'un RDV (reschedule)

## Dev Notes

### Logique de chevauchement

Deux creneaux se chevauchent si : `startA < endB AND endA > startB`

```typescript
const conflict = await this.appointmentRepository
  .createQueryBuilder('apt')
  .where('apt.practitionerId = :practitionerId', { practitionerId })
  .andWhere('apt.tenantId = :tenantId', { tenantId })
  .andWhere('apt.status != :cancelled', { cancelled: 'CANCELLED' })
  .andWhere('apt.startAt < :endAt', { endAt })
  .andWhere('apt.endAt > :startAt', { startAt })
  .getOne();

if (conflict) {
  throw new ConflictException({
    message: 'Conflit de creneau detecte',
    existingAppointment: {
      id: conflict.id,
      startAt: conflict.startAt,
      endAt: conflict.endAt,
      patientId: conflict.patientId,
    },
  });
}
```

### Status des RDV

L'enum de status backend utilise : `BOOKED`, `CANCELLED`, `DONE`, `NO_SHOW`. Seuls les RDV avec status != `CANCELLED` sont des conflits. [Source: architecture.md#data-models]

### Frontend — gestion erreur 409

```typescript
try {
  await AppointmentService.createAppointment(data);
} catch (error) {
  if (error.status === 409) {
    toast.error('Ce praticien a deja un rendez-vous sur ce creneau');
  } else {
    toast.error(handleApiError(error));
  }
}
```
