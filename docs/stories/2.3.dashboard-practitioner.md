# Story 2.3: Dashboard PRACTITIONER avec donnees reelles

## Status: Ready for Review

## Story

**As a** praticien,
**I want** voir mes vrais rendez-vous, patients et consultations sur mon dashboard,
**so that** je puisse travailler efficacement sans donnees fictives.

## Acceptance Criteria

1. Remplacement des donnees hardcodees par des appels API filtres par `practitionerId`
2. Section "Mes RDV du jour" avec donnees reelles et horaires
3. Section "Activite recente" avec les dernieres consultations, prescriptions, RDV
4. Stat cards avec donnees API : RDV aujourd'hui, Patients actifs, Consultations cette semaine
5. Etat de chargement (skeleton) pendant le fetch
6. Etat vide si aucun RDV ("Aucun rendez-vous aujourd'hui")
7. Actions rapides avec liens vers : Nouveau RDV, Nouvelle consultation, Mes patients

## Dev Notes

### Donnees actuellement hardcodees a supprimer

Le fichier `app/practitioner/dashboard/page.tsx` contient des donnees fictives :
- "Marie Dubois" / "Consultation de suivi" / "09:30"
- "Jean Martin" / "Premiere consultation" / "10:15"
- "Sophie Leroy" / "Controle post-operatoire" / "11:00"
- Stats hardcodees : "8" RDV, "156" patients, "24" consultations, "25min" temps moyen

Tout doit etre remplace par des appels API reels. [Source: architecture.md#component-architecture]

### Services a utiliser

- `AppointmentService.getAppointments()` — avec filtre `practitionerId`
- Pour les encounters : utiliser le service encounters existant avec filtre `practitionerId`
- Le `practitionerId` vient de `useAuth().practitioner?.id` ou `useAuth().user?.id` selon le type de login

### Identification du praticien

Le praticien peut etre connecte via :
- `useAuth().practitioner` (login via `/auth/practitioner/login`)
- `useAuth().user` avec role PRACTITIONER (login via `/auth/login`)

Utiliser `practitioner?.id || user?.id` comme `practitionerId` pour les appels API. [Source: architecture.md#ADR-1]

### Testing

- **Verification :** Test manuel. Login praticien → dashboard avec donnees API. Verifier les RDV, stats, etats vide/loading.
