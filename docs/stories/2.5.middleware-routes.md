# Story 2.5: Middleware de protection des routes par role

## Status: Ready for Review

## Story

**As a** operateur de la plateforme,
**I want** que chaque role ne puisse acceder qu'a ses routes autorisees,
**so that** l'acces non autorise soit empeche meme en tapant l'URL directement.

## Acceptance Criteria

1. Definition d'une map role → routes autorisees
2. `SUPERADMIN` : uniquement `/admin/*`
3. `ACCOUNTANT` : uniquement `/accounting/*`, `/profile`
4. `PRACTITIONER` : `/practitioner/*`, `/patients`, `/encounters`, `/appointments`, `/profile`
5. `EMPLOYEE` : `/dashboard`, `/patients`, `/appointments`, `/queue/*`, `/accounting/invoices`, `/profile`
6. `CLINIC_ADMIN` : toutes les routes cliniques + `/admin/users`
7. Redirection vers le dashboard du role si acces non autorise
8. Les routes publiques restent accessibles sans authentification

## Dev Notes

### Limitation du middleware Next.js (ADR-2)

Les tokens sont dans `localStorage`, inaccessible au middleware server-side. La protection de route se fait donc en 2 couches :
1. **Middleware Next.js** : verification de la presence d'un token (leger, deja en place)
2. **Composant React (useRoleGuard)** : verification du role et redirection

[Source: architecture.md#ADR-2]

### Approche recommandee

Creer un composant `RoleGuard` utilise dans `MainLayout` :

```typescript
function RoleGuard({ children }) {
  const { user, practitioner } = useAuth();
  const router = useRouter();
  const pathname = usePathname();
  const role = user?.role || (practitioner ? 'PRACTITIONER' : null);

  useEffect(() => {
    if (!role) return;
    const allowedRoutes = ROLE_ROUTES[role] || [];
    const isAllowed = allowedRoutes.some(route => pathname.startsWith(route));
    if (!isAllowed) {
      router.push(ROLE_DASHBOARD[role] || '/dashboard');
    }
  }, [role, pathname]);

  return children;
}
```
